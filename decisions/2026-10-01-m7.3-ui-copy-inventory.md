# M7.3 UI copy inventory: save, open, recovery, history, backup

Status: copy artifact for Kanban task `t_a2af0393` (Wheeljack, M7.3). Authored by Arcee on `t_9b9929c5`, read-only against `src/persistence/*` and the M7/M7.1/M7.2 decision records. Not a commit to `src/`.

Every string below is final text to integrate verbatim. `<angle brackets>` mark a runtime value to interpolate; everything else is literal, including punctuation and capitalization. Placeholders:

- `<title>` — `document.show.title` (or `freeformFilename` with extension stripped, for filenames)
- `<filename>` — the resolved `.freeform` filename
- `<timestamp>` — a localized date/time, e.g. "Oct 1, 2026, 3:42 PM"; never a raw epoch number
- `<version>` — `formatVersion`, e.g. "1.1.0"
- `<message>` — the lower-level `Error.message` a service already returns; used only where noted

## Terminology decisions (apply across all sections)

1. "Local backup" is the user-facing noun for the IndexedDB working copy everywhere, including the `RecoveryCandidate.source` value `indexeddb-working-copy`. There is no other source value today, so the UI never needs to disambiguate sources; if a second source value is ever added, this inventory must be revisited.
2. "Version history" / "version" stays as-is. It is a familiar pattern (Google Docs, Word) and not implementation jargon, unlike "checkpoint" — so this one noun is kept against the card's general ban on service-layer nouns, deliberately, for clarity.
3. "Revision" is never shown. A `WriteOutcome` of `stale-revision` gets no user-facing copy at all: per the M7.2 decision, this is an autosave race where the newer write already won, so there is nothing wrong to report and nothing the user can act on. If a future caller other than autosave ever needs to react to it, that caller needs new copy — flag it to Wheeljack rather than inventing a message now.
4. "IndexedDB" never appears. "Local storage" or "this browser's local storage" stands in for it everywhere a message must explain *why* something is local-only.
5. `formatVersion` is shown as "format <version>" (e.g. "format 1.0.0"), never "schema version" or "schemaVersion".
6. Every error message pairs the problem with (a) what the user can do next and (b) a flat assurance the open document is untouched, per the card's requirement — these are not generic toasts, each is written against its specific trigger.

## 1. Save / Save As / download — success and failure

Controls:
- Primary control: **Save** (`Ctrl+S` / `Cmd+S`). Calls `saveExplicitSnapshot` with `operation: 'save'`.
- Secondary control: **Save As…**. Calls `saveExplicitSnapshot` with `operation: 'save-as'`.
- Neither control is separately labeled "Download" — when no File System Access handle or picker is available, the same two controls silently use the download fallback. The user never has to know which path ran until the result tells them.

Results (`SaveResult`):

| Trigger | Toast / inline text |
|---|---|
| `ok:true, method:'file-system-access'` | "Saved." (chrome state label switches to Saved — see §2) |
| `ok:true, method:'download'` (Save) | "Downloaded <filename>. Your browser doesn't have permission to overwrite files directly, so each save creates a new download." |
| `ok:true, method:'download'` (Save As, no picker available) | "Downloaded <filename> to your browser's downloads folder." |
| `ok:false, reason:'permission-denied'` | "Freeform couldn't get permission to save to <filename>. Use Save As to pick a file you can grant access to. Your document is unchanged and still open." |
| `ok:false, reason:'cancelled'` | No dialog. The save picker was dismissed by the user; the chrome state label simply stays "Unsaved changes" (§2). A quiet, auto-dismissing toast is permitted: "Save cancelled." |
| `ok:false, reason:'write-failed'` | "Freeform couldn't finish saving <filename> (<message>). Your document is unchanged and still open — try again, or use Save As to save a new copy." |
| `ok:false, reason:'download-failed'` | "Freeform couldn't download a copy of your show (<message>). Your document is unchanged and still open — check your browser's download settings and try again." |

Note for Wheeljack: `download-failed` also fires when no download adapter exists at all (`environment.download` undefined); same copy applies, `<message>` becomes "No download adapter is available in this environment." in that branch, which is acceptable as-is since it's a developer-environment edge case, not a real browser path.

## 2. Persistent chrome state label

One status chip, five mutually exclusive states (autosaving is transient and always resolves back to Saved/Unsaved/Local backup failed):

| State | Label | Tooltip / expanded text |
|---|---|---|
| Clean | **Saved** | "Your document matches the last file you saved." |
| Dirty | **Unsaved changes** | "Press Ctrl+S (Cmd+S on Mac) to save your file. Freeform also keeps a local backup automatically." |
| Autosaving (transient, `writeWorkingCopy` in flight) | **Saving local backup…** | "Freeform is copying your latest edits to this browser's local storage. This isn't the same as saving your file." |
| Local-failure (`WriteOutcome.ok:false`, reason `unavailable` / `quota-exceeded` / `storage-error`) | **Local backup failed** | See §7 for the three distinct reason texts — same wording reused here. |
| Read-only | **Read-only — newer file format** | "This show was saved by a newer version of Freeform. You can look around and export the original file, but you can't edit or save changes." |

`stale-revision` outcomes never reach this label (see Terminology decision 3) — the chip stays in whichever state it was already in.

## 3. Startup recovery candidates

Panel header: **Recover unsaved work?**
Intro text: "Freeform found local edits to “<title>” that are newer than the last file you saved. Choose what to do with them."

Each `RecoveryCandidate` row:

> **<title>** — local backup from <timestamp> (format <schemaVersion>)

Four actions per row:

1. **Open as a copy** — "Open this local backup as a separate document so you can look it over before deciding." (`loadCandidate`; does not touch current working state.)
2. **Replace current with this** — opens the confirmation dialog below. (`confirmReplace`.)
3. **Export backup** — "Download this local backup as a .freeform file without changing anything." (`exportBackupBytes`.)
4. **Discard** — "Delete this local backup. Your explicit file, if any, is not affected." (`discardCandidate`.) No confirmation dialog is required here because discarding only removes an unsaved local copy, not a saved file — but it must not be the row's default/pre-focused action.

Confirm-replace dialog (triggered by action 2):

> **Replace your current document?**
> This replaces everything currently open with the local backup of "<title>" from <timestamp>. Anything you have open right now that isn't already saved will be lost. This can't be undone.
>
> [Cancel] [Replace]

`CandidateLoadResult` failure copy (applies to both "Open as a copy" and "Replace current with this"):

- `reason:'invalid'` — "Freeform couldn't open this local backup — it may be damaged, or saved in a format this version can't read (<message>). Your currently open document hasn't changed. You can still discard it." (Discard remains enabled.)
- `reason:'not-found'` — "This local backup is no longer available — it may already have been opened or discarded." (Soft notice; refresh the candidate list and remove the row.)

## 4. Version history and restore

Panel header: **Version history**

`CheckpointSource` row labels:

| Source | Label |
|---|---|
| `explicit-save` | Saved version |
| `import` | Imported file |
| `pre-destructive` | Automatic backup before a big change |
| `migration-original` | Original file (before format upgrade) |

Row template: **<Saved version>** — <timestamp>, <sizeBytes formatted as KB/MB>

Each row has a **Restore this version** control.

Restore confirmation dialog:

> **Restore this version?**
> This makes the version from <timestamp> your current working document. It stays in your version history afterward — restoring doesn't delete or move it, so you can always come back to today's version too. Anything in your current document that isn't saved or backed up yet will be lost.
>
> [Cancel] [Restore]

The second sentence is the required disclosure that the source checkpoint is preserved, not deleted, on restore.

## 5. Backup

Controls:
- **Choose backup folder…** — destination picker. Helper text under the control: "Optional. Without a folder, Back Up Now downloads a file instead."
- **Back up now** — user-triggered `writeBackup`.
- Retention disclosure, shown near the destination picker once a folder is chosen: "Freeform keeps your 10 most recent backups for this show in this folder and deletes older ones with the same name automatically. If you rename the show, older backups under the old name are left alone — you'll need to clean those up yourself."

Scheduled reminder prompt (pure 24h boolean gate — `shouldPromptForBackup`):

> **Back up your show?**
> It's been a day since your last backup prompt. Want to back up a copy now? Freeform only checks this while the app is open in this tab — it doesn't back up on a background schedule.
>
> [Remind me tomorrow] [Back up now]

"Remind me tomorrow" dismisses and records `lastPromptedAt`, so the next prompt is honestly 24 hours out — it does not claim "never" or imply a guaranteed future reminder if the tab isn't open then.

`BackupResult` outcomes:

| Trigger | Text |
|---|---|
| `ok:true, method:'filesystem'` | "Backup saved as <filename> in your chosen folder." |
| `ok:true, method:'download'` | "Backup downloaded as <filename>. Choose a backup folder to skip the download step next time." |
| `ok:false, reason:'write-failed'` | "Freeform couldn't write a backup to your chosen folder (<message>). Try again, or back up using a download instead." |
| `ok:false, reason:'no-destination'` | "Freeform doesn't have a backup folder chosen yet. Choose a folder, or back up now to download a copy instead." |

Note for Wheeljack: `writeBackup`'s current implementation never actually returns `no-destination` — when `destination` is `undefined` it falls through to the download branch instead. The text above is supplied in case a future caller distinguishes that state deliberately; flag back to Arcee if the behavior changes so this row can be revisited against the real trigger.

## 6. Future-major file (read-only)

Banner (persistent, non-dismissible while the file is open):

> **Read-only: newer file format**
> This show was saved with Freeform format <version>, which is newer than this app understands. Nothing here can be edited or saved. You can export the original file exactly as it is.
>
> [Export original file]

"Export original file" downloads `originalBytes` unchanged — the control deliberately does not say "export bytes" to avoid implementation jargon, and never offers "Save" or "Save As" in this state.

Disabled-control tooltip (hover on Save, any edit tool, Undo/Redo while in this state): "Editing is turned off because this file uses a newer format than this app supports."

## 8. Unsaved-document switch / open / new confirmation

No silent discard anywhere — every path below ends in an explicit three-button choice naming Save.

Switching/opening a different file while dirty:

> **Save your changes first?**
> "<title>" has unsaved changes. Opening a different file without saving will lose them.
>
> [Cancel] [Discard and Open] [Save and Open]

Starting a new show while dirty:

> **Save your changes first?**
> "<title>" has unsaved changes. Starting a new show without saving will lose them.
>
> [Cancel] [Discard and Start New] [Save and Start New]

If the save step inside either compound action fails (any `SaveResult.ok:false`), the switch/open/new is cancelled, the dialog's underlying failure text from §1 is shown, and the document stays open exactly as it was — the app never proceeds to discard after a failed save.

## 9. Keyboard shortcuts and help text

Help panel / tooltip entries:

| Action | Shortcut shown | Help text |
|---|---|---|
| Save | Ctrl+S (Windows/Linux) · Cmd+S (Mac) | "Saves your show to its file." |
| Undo | Ctrl+Z (Windows/Linux) · Cmd+Z (Mac) | "Undoes your last show edit. While you're typing in a text field, this uses your browser's normal text undo for that field instead." |
| Redo | Ctrl+Y or Ctrl+Shift+Z (Windows/Linux) · Cmd+Shift+Z (Mac) | "Redoes the last thing you undid. Like Undo, this doesn't apply while you're typing in a text field — your browser handles redo there." |

This matches spec §5: shortcuts don't fire while editing ordinary text, and the help text says so explicitly rather than implying Freeform's undo stack always wins.
