# Freeform traceability, benchmark, and milestone corrections

Status: accepted corrections for Kanban task `t_485a6c50`, made in response to independent verification `t_5ef08991` (FAIL) of `docs/freeform-mvp-spec-v1.md` at commit `485a588`.

DECISION | Wheeljack | IDEA.md line 7 formation-placement traceability | Add MVP MUST-level line and circular-arc arrangement tools (new §4.3) that redistribute a selected group of performers' dots within one set at equal spacing; curvilinear/free placement is satisfied by the existing MUST direct manual dot-editing capability (§1); update §9 traceability accordingly | The verification report found IDEA.md line 7's "lines, arcs, curvilinear, free, and other shapes" placement requirement was claimed traceable to §§3-4 but those sections only specify step-size/FTL motion, not within-set formation arrangement; the requirement was neither implemented-in-spec nor explicitly deferred | Line/arc tools are new spec surface for an implementation card to build (not implemented here); curvilinear/free coverage relies on manual placement already specified, so no new geometry engine requirement was introduced.
DECISION | Wheeljack | Pair-distance utility MUST/SHOULD level | Revert the pair-distance-in-steps utility from an unauthorized implicit MUST (§1 bullet list, §9 row) back to SHOULD, matching J's fixed decision in `decisions/2026-09-28-mvp-specification-decisions.md` ("Motion safety semantics") | The verification report found the utility had been silently promoted from SHOULD to MUST with no recorded J decision authorizing the promotion; no such promotion decision exists | If the utility later needs to be a hard MVP dependency (e.g. another MUST feature relies on it always being present), that requires an explicit new J decision, not a spec drafting choice.
DECISION | Wheeljack | Performance benchmark fixture topology | Change the baseline fixture from 250 ordered sets / 499 float transitions to 250 ordered sets / 249 float transitions, keeping J's 500 performer / 250 set / 10,000 total-count / >=30 fps targets unchanged | §4 defines a transition as joining adjacent ordered sets; an adjacent chain over 250 ordered sets has exactly 249 transitions, so 499 was topologically impossible to construct from 250 sets under the spec's own transition model | The benchmark now describes a buildable fixture; total-count and fps targets, which were correct, are preserved exactly as J specified.
DECISION | Wheeljack | Milestone dependency graph for persisted state | Change M7 (persistence) dependencies from M1, M4 to M1, M4, M5, M6, and split the former M9 ("setup wizard, accessibility, browser/performance hardening") into four atomic milestones M9 setup wizard (depends on M1), M10 accessibility hardening, M11 cross-browser functional hardening, and M12 performance benchmark validation (M10-M12 each depend on M1-M8) | The verification report found M7 could be accepted before collision overrides (created by M5) or annotation/layer state (created by M6) existed, since persistence must cover documented override and annotation/layer data per §6; it also found the former M9 bundled four independently gatable evidence artifacts (wizard tests, WCAG audit, three-browser matrix, performance run) into one milestone, so a partial failure in any one blocked crediting the others | M7 acceptance now requires collision-override and annotation/layer persistence integration tests in addition to the prior quota/permission/malformed/migration tests; M9-M12 can be evidenced and accepted independently once the M1-M8 functional baseline is done, improving schedule legibility without changing total scope.
DECISION | Wheeljack | Traceability table accuracy | Split the former combined "IDEA.md line 7: 8-to-5, float, FTL, step feedback" traceability row into a formation-placement row (new MUST via §4.3) and a motion/step-feedback row (§4, §4.1 MUST); reclassify the collision/pair-distance row into a MUST collision-override row (§4.2) and a separate SHOULD pair-distance row | A single combined row previously implied uniform MUST disposition across requirements that in fact split MUST vs. SHOULD, and omitted the formation-placement requirement entirely | Traceability now gives one honest disposition per distinct source requirement; no source requirement is silently dropped and no SHOULD is silently promoted to MUST.

Scope note: this card is corrections to `docs/freeform-mvp-spec-v1.md` only (§1, §4, §4.2-4.3, §7, §8, §9); it does not implement application code, and it does not address the separately carded step-size math (item A), schema/validator coverage (items B, C), or edge-semantics items (F) from the `t_5ef08991` verification report — those are in scope for sibling cards `t_5abaf2f9` and `t_021f8fd2`.
