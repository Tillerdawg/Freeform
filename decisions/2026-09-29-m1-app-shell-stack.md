# M1 app-shell technology choice

Status: accepted implementation decision for Kanban task `t_e8ad44cb`.

DECISION | Wheeljack | M1 application stack and rendering boundary | Use TypeScript + Vite with vanilla TypeScript/DOM APIs; render the M1 shell using semantic HTML/CSS. Adopt SVG as the future field-rendering surface, beginning when M2 introduces canonical field geometry. | J approved TypeScript + Vite without a UI framework. Vite produces a deployable static asset bundle with an uncomplicated development server, while vanilla DOM keeps the initial editor-state boundary independent of a UI runtime. SVG is preferable to canvas for the future editable field because its addressable elements remain inspectable and can be paired with semantic accessibility affordances; M1 has no geometry renderer and therefore does not render a placeholder field. | M1 has no backend or runtime network dependency after assets load. The immutable command store is the document-to-geometry/motion boundary: later geometry/motion code receives read-only canonical document state and returns derived output without owning document mutation. Future M2 rendering must retain canonical field units as source-of-truth and must not persist SVG pixels.
